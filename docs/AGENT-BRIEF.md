# Бриф для текстового агента

Этот файл — то, что агент должен прочитать первым. Полная спека:
`docs/TEXT-PIPELINE.md`.

---

## Твоя роль

Ты заполняешь **только формулировки правил**. Структуру проекта ведёт другая
роль: id, очки, CP, ключевые слова, профили, механика, UI, сборка, деплой.

## Единственный файл, который ты редактируешь

```
text/<faction>.slots.json
```

Больше ничего. Список запретов ниже — он жёсткий.

### НИКОГДА

- **Не редактируй `data.js`.** Это сгенерированный файл. Правка руками ломает
  сборку и создаёт конфликты. Он собирается командой из слот-файлов.
- Не трогай `app.js`, `engine.js`, `sw.js`, `index.html`, `version.json`,
  `VERSION`, `manifest.webmanifest`.
- Не меняй поля, начинающиеся с `_` (`_name`, `_cp`, `_pts`, `_type`,
  `_phases`, `_kind`). Это подписи, не данные. Если их изменить — сборка
  откажется работать целиком.
- Не добавляй и не удаляй ключи. Не переставляй блоки. Не переименовывай id.
- Не мержи в `main`. Работай только в ветке `rules-fidelity-fix`.
- Не правь очки, CP и стоимости. Даже если видишь ошибку — сообщи, не меняй.

Если кажется, что нужно новое поле или новая запись — это изменение
структуры. Напиши об этом и остановись, не придумывай своё.

## Рабочий цикл

```bash
git checkout rules-fidelity-fix
git pull

node tools/gen-slots.js          # обновить слоты из текущего data.js

#   -> редактируешь text/<faction>.slots.json

node tools/merge-text.js --dry   # показать, что изменится, ничего не писать
node tools/merge-text.js         # применить в data.js
node tools/validate-data.js      # ворота: ошибки блокируют деплой
node tools/release.js            # поднять маркеры версии

git add -A && git commit -m "..." && git push origin rules-fidelity-fix
```

Или одной командой после редактирования: `npm run ship`.

**Начинай всегда с `git pull` и `node tools/gen-slots.js`.** Слот-файлы
протухают, если `data.js` изменился.

## Как устроена адресация

Ты не выбираешь, куда класть текст. Каждый пропуск уже стоит на своём месте
под своим `id`. Рядом стоит подпись `_name` — по ней видно, какая это
запись. Твоя задача — заполнить пропуск, а не решить, куда он относится.

Какое поле что означает:

| Что ты пишешь | Куда |
|---|---|
| название чего угодно | **никуда** — названия уже заданы, показаны в `_name` |
| когда стратагему можно применить | `when` |
| на что она применяется | `target` |
| что она делает | `effect` |
| ограничение применения | `restrictions`, или `null` если нет |
| что делает enhancement | `text` |
| что делает способность юнита | `text` внутри этой способности, внутри этого юнита |
| правило армии, по абзацам | `text` — это **список**, абзац = элемент |

## Как писать текст

- **Только простой текст.** Никакого HTML, markdown, `**жирного`, `[скобок]`
  для выделения. Движок экранирует разметку — она вылезет на экран как есть.
- **Выделение ставится само.** Не размечай ключевые слова вручную. Подсветка
  строится автоматически из КАПСА, нотации кубов, названий фаз и списка
  терминов фракции.
- Сохраняй КАПС как в источнике — именно он даёт подсветку ключевых слов.
- Кубы пиши как `D6`, `D3`, `2D6`, `D6+3`. Не `d6`, не `D-6`.
- Фазы пиши с большой: `Shooting phase`, не `shooting phase`.
- Дюймы `"` и плюсы в спасбросках `+` сохраняй.
- Не удаляй ключ, если запись ещё не сделана — оставь как есть.

## Ворота

`node tools/validate-data.js` должен закончиться на `PASS`.

Если `FAIL` — **не коммить и не пушь**. Почини то, на что он ругается, и
прогони снова. Коды ошибок описаны в `docs/TEXT-PIPELINE.md`.

Если `merge-text.js` написал `ABORTED — context mismatch` — значит ты
изменил подпись `_`. Не правь её обратно руками. Сделай
`node tools/gen-slots.js <faction>` и перенеси формулировки заново.

Предупреждения `W-UNTERMINATED` и `W-ELLIPSIS` — признак того, что запись
оборвалась на середине. Проверь их в первую очередь.

## Порядок работы

Делай **одну фракцию и одну категорию за заход**, затем прогоняй ворота и
коммить. Мелкими коммитами. Так падение посреди работы не оставит базу в
смешанном состоянии — именно это случилось в прошлый раз и положило
открытие всех пяти армий.

В конце каждого захода отчитайся: какая фракция, какая категория, сколько
записей, результат `validate-data.js`.

Откуда берутся формулировки и на каких условиях — твоя зона
ответственности. Пайплайн определяет только куда их класть и в каком виде.
