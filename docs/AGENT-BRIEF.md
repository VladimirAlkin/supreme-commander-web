# Бриф для текстового агента

Прочитай целиком перед первым действием. Правила жёсткие, потому что
прошлые заходы ломали приложение.

---

## Твоя роль

Ты находишь точные формулировки правил и складываешь их в одно место.
**Всё.** Ты не правишь приложение, не правишь данные, не решаешь, куда
какой текст относится. Это делает структурная роль после тебя.

Откуда ты берёшь формулировки и на каких условиях — твоя зона
ответственности. Здесь описано только куда их класть и в каком виде.

---

## Единственное место, куда ты пишешь

```
text/inbox/
```

Больше ничего. Ни одного файла за пределами этой папки.

### НИКОГДА, ни при каких обстоятельствах

- **`data.js`** — не открывать, не править, не «поправить мелочь». Это
  сгенерированный файл. Любая правка руками ломает сборку.
- `app.js`, `engine.js`, `style.css`, `sw.js`, `index.html`,
  `manifest.webmanifest`, `version.json`, `VERSION`, `tools/`, `docs/`
- Не менять очки, CP, стоимости, ключевые слова, характеристики, `id`,
  `coreAbilities`, `kind`, buff'ы, правила опций — **ничего из механики**.
  Увидел ошибку в числах — напиши об этом текстом, не исправляй.
- Не придумывать новые поля и новые записи.
- Не мержить в `main`.

Проверка на входе: если твоя правка не в `text/inbox/` — ты делаешь
что-то не то. Остановись.

### Почему так строго

Не абстракция. Что уже случалось:

- Запись buff'а была заменена на форму с ключами `condition`/`duration`,
  которых движок не читает. Это роняло `render()` — и приложение зависало
  целиком: не открывался ни один юнит, не работали датащиты, кнопка «назад»
  выходила из приложения. Чинилось полдня.
- Из юнитов пропали `coreAbilities`: Deep Strike, Leader, Scouts 6",
  Super-Heavy Walker. Правила молча стали неверными.
- Половина правил армий была сконвертирована из списка в строку, после чего
  падали страницы всех пяти армий.

Одна битая строка данных вешает всё приложение, и симптом никогда не
указывает на данные. Поэтому к структуре тебя не пускают.

## Как сдавать работу

Один файл на фракцию и категорию:

```
text/inbox/<faction>.<category>.md
```

`<faction>`: `worldEaters` `tyranids` `deathGuard` `thousandSons` `adeptaSororitas`

`<category>`: `stratagems` `enhancements` `detachment-rules` `army-rules` `unit-abilities`

Например: `text/inbox/deathGuard.stratagems.md`

### Формат — обычный текст, ничего больше

Каждая запись начинается с `## ` и её названия **точно так, как оно
написано в приложении**. По названию я найду запись сам, `id` тебе знать
не нужно.

**Стратагемы** — три подписанных поля, четвёртое по необходимости:

```
## Cleansing Flames
WHEN: Your Shooting phase.
TARGET: One ADEPTA SORORITAS unit from your army that has not been selected to shoot this phase.
EFFECT: Until the end of the phase, Torrent weapons equipped by models in your unit have the [DEVASTATING WOUNDS] ability.
RESTRICTIONS:
```

**Enhancements, правила детачментов** — название и текст:

```
## Chaplet of Sacrifice
Текст правила одним абзацем.
```

**Правила армий** — абзацы разделяй пустой строкой, порядок сохраняй:

```
## Acts of Faith
Первый абзац.

Второй абзац.
```

**Способности юнитов** — обязательно через имя юнита, иначе непонятно, чья
это способность (одинаковые названия встречаются у разных юнитов):

```
## Plague Marines :: Remorseless
Текст способности.
```

### Правила написания

- Только простой текст. Никакого HTML, markdown-разметки внутри текста,
  `**жирного`, `[скобок]` для выделения. Движок их экранирует — разметка
  вылезет на экран как есть.
- **Выделение ключевых слов ставится само.** Размечать ничего не надо.
- Сохраняй КАПС как в источнике — именно он даёт подсветку.
- Кубы: `D6`, `D3`, `2D6`, `D6+3`. Не `d6`, не `D-6`.
- Фазы с большой буквы: `Shooting phase`.
- Дюймы `"` и плюсы в спасбросках `+` сохраняй.
- Нет записи — просто не пиши её. Пустой блок не нужен.
- Название в `## ` не переписывай и не переводи. По нему идёт поиск.

## Порядок работы

```bash
git checkout <ветка, которую назвала структурная роль>
git pull
#  ... пишешь только в text/inbox/ ...
git add text/inbox
git status          # в списке не должно быть НИЧЕГО кроме text/inbox/
git commit && git push
```

`git status` перед коммитом — обязательный шаг. Увидел там что-то кроме
`text/inbox/` — откати это, не коммить.

**Одна фракция и одна категория за заход.** Потом коммит. В прошлый раз
падение посреди большого захода оставило данные в полусконвертированном
виде и положило приложение.

В конце захода отчитайся: фракция, категория, сколько записей, и всё ли
нашлось. Если какой-то записи не нашёл — так и скажи, не выдумывай.

## Что происходит дальше

Структурная роль запускает:

```
tools/check-agent-scope.js   отказ, если ты тронул что-то вне inbox
tools/ingest-inbox.js        сопоставляет названия с записями приложения
tools/merge-text.js          кладёт текст в data.js (только текстовые поля)
tools/validate-data.js       ворота: ошибки блокируют деплой
tools/mechanics-diff.js      доказывает, что механика не изменилась
tools/release.js             версия и кэш
```

Названия, которые не нашлись, тебе вернут списком. Ничего не угадывается.
